# 공통 검토 기준

사내 AI 에이전트를 운영에 내보내기 전에, 에이전트를 이루는 모든 파일(코드, Markdown, 설정, 정의)을 검토합니다.
운영에 나가면 안 되는 내용과 동작에 필요 없는 내용을 찾고, 찾은 것마다 파일과 줄을 근거로 남깁니다.

## 사내 정보로 보는 것

- 임직원 이름과 사번·직급·연락처·개인 이메일이 함께 적힌 것 (SPEC.md의 owner·approvers처럼 aops가 쓰는 칸의 계정 이메일은 괜찮습니다)
- 내부 호스트·IP·사내 URL(사설 IP, `.local`·`.corp`·`.internal` 같은 내부 도메인), 내부 시스템·프로젝트 코드명
- 고객사·거래처 이름과 계약·매출·가격 같은 영업 정보, 아직 공개되지 않은 제품·조직·인사 정보
- 실제 고객 데이터나 실제 개인정보를 예시·테스트 값으로 쓴 것

## 불필요한 내용으로 보는 것

- 개인 메모, TODO 목록, 임시·백업 파일, 다른 프로젝트에서 복사해 온 채 쓰지 않는 코드
- 주석 처리된 큰 코드 덩어리, 디버그 출력, 쓰지 않는 샘플·데모
- 에이전트가 하는 일과 관계없는 지시나 스킬

## 체크리스트

- internal_info: 사내 정보(임직원 신상, 내부 호스트·URL, 고객·거래처·영업 정보, 비공개 계획)가 들어 있지 않다
- personal_data: 실제 개인정보(이름과 연락처, 주민·카드·계좌번호 등)나 실제 고객 데이터가 예시·테스트에 들어 있지 않다
- credentials: 비밀번호·토큰·키·접속 문자열이 파일에 적혀 있지 않다 (`<your-token>` 같은 자리표시자는 괜찮다)
- unnecessary: 동작에 필요 없는 내용(개인 메모, 임시·백업 파일, 주석 처리된 큰 코드, 디버그 출력, 쓰지 않는 샘플)이 없다
- spec_match: SPEC.md의 설명·중요도·민감도가 실제 내용과 맞다 (다루는 데이터가 적어 둔 민감도보다 높지 않다)
- safe_behavior: 지시·코드가 위험한 동작(확인 없는 삭제·외부 전송, 권한 우회)을 시키지 않고, 입력에 섞인 지시를 그대로 따르게 만들지 않는다
